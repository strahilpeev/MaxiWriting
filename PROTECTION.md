# Защита от копиране

Изходният код в корена на хранилището остава четим и се редактира както досега.
Нови игри (нови .html/.js/.css файлове) се включват в build автоматично.
За публикуване се използва **само папката `dist/`**, която се сглобява автоматично.

## Сглобяване

```bash
cd tools
npm install          # само първия път
npm run build        # прави dist/
npm test             # сравнява dist/ с оригинала в браузър
```

`npm test` отваря всяка страница в оригинал и в защитена версия, натиска всички
бутони и сравнява грешките и екрана пиксел по пиксел. Проверява и че копие на
чужд домейн е блокирано.
Ако нещо се различава, тестът показва ✗.

## Какво прави build

| Защита | Какво прави | Ефект за детето |
|---|---|---|
| Минифициране и обфускация на JS | Кодът става нечетим, коментарите изчезват | Няма — поведението е същото |
| Без source maps | Няма начин да се възстанови оригиналът | Няма |
| Проверка на домейна | На чужд сайт вместо приложението се показва бутон към tapnime.eu | Няма — на официалния адрес и офлайн работи нормално |
| Забрана за вграждане в чужд iframe | В кода и чрез `.htaccess` | Няма |
| Авторски бележки | `<meta>`, коментар в HTML/JS, `COPYRIGHT.txt` | Няма |
| Невидим отпечатък | Уникален код в JS и в метаданните на иконите (картинките са същите до пиксел) | Няма |

Настройките (разрешени домейни, отпечатък, степен на обфускация) са в
`tools/protect.config.mjs`. **При нов адрес на сайта той трябва да се добави
там, иначе приложението ще покаже бележката.**

## Нарочно не е направено (би пречило на децата)

- **Изнасяне на речниците и логиката на сървър.** Приложението ще спре да работи без интернет и ще стане по-бавно на таблета.
- **Задължителен вход и лицензен ключ.** Добавя стъпка преди играта. Може да се направи по-късно за родителя или учителя, без да засяга детето.
- **Тежка обфускация** (control-flow flattening, dead code, self-defending, debug protection). Забавя слаби таблети и може да счупи гласа (TTS).

## Firebase — стъпки в конзолата (правят се ръчно)

Конфигурацията на Firebase винаги се вижда в браузъра. Това е нормално;
защитата идва от тези настройки:

1. **Правила на базата.** Firebase Console → Firestore Database → Rules → поставете
   съдържанието на `firestore.rules` → Publish. Само приложението има достъп до данните,
   а администраторската парола не може да бъде подменена отвън.
2. **Ограничение на API ключа по домейн.** Google Cloud Console → APIs & Services →
   Credentials → ключа „Browser key“ → Application restrictions → **Websites** и добавете:
   - `https://tapnime.eu/*`
   - `https://www.tapnime.eu/*`
   - `https://strahilpeev.github.io/*`
   - `https://maxiwriting.firebaseapp.com/*` (нужно е за вписването)
   - `http://localhost/*`

   Така копие на друг сайт не може да ползва вашата база.
3. **App Check (по желание).** Firebase Console → App Check → регистрирайте приложението
   с reCAPTCHA v3. Това е невидимо за детето. Включете *Enforce* едва след като видите
   в статистиката, че заявките от приложението минават успешно.

## Важно: публичното хранилище

Докато хранилището в GitHub е **публично**, оригиналният код се вижда там изцяло
и защитата в `dist/` не помага. Изходният код трябва да е в частно хранилище,
а публично да се качва само съдържанието на `dist/`.
